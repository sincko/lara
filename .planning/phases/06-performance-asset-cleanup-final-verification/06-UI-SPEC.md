### Font-loading contract (the core of this phase — PERF-01)

| Property | Today (locked baseline) | After (contract target) |
|----------|--------------------------|--------------------------|
| Families loaded | "Ubuntu" (400+700), "Parisienne" (400) | **identical** — same two families, same weights |
| Font-family CSS vars | `--font-family: "Ubuntu", sans-serif; --font-family-titles: "Parisienne", cursive;` | **unchanged** (D-02) — same names, same fallback stacks (this IS the failure-state contract) |
| font-display | `swap` (both Google URLs carry `&display=swap`) | `swap` — **inherent** in @fontsource 5.3.0 CSS (verified in package: `font-display: swap` on every `@font-face`) (D-04) |
| Subset delivery | Google css2 returns unicode-range split (cyrillic-ext…latin) | @fontsource CSS ships the **same unicode-range subsetting** (verified: latin/cyrillic/greek blocks per weight) |
| Load mechanism | Two render-blocking `@import url(https://fonts.googleapis.com/…)` at style.scss:7-8 | Self-hosted WOFF2 bundled into the site CSS — zero Google requests, zero render-blocking css fetch |
| File formats | WOFF2 (Google) | WOFF2 (with WOFF fallback in the css) — same effective format |

**Mechanism (empirically resolved 2026-08-20 against dart-sass 1.102.0 in this repo):**

Replace style.scss lines 7-8 with **`@use` of the fontsource CSS with an `as` namespace** — this is mandatory, verified:

```scss
@use "@fontsource/ubuntu/400.css" as ubuntu400;
@use "@fontsource/ubuntu/700.css" as ubuntu700;
@use "@fontsource/parisienne/400.css" as parisienne400;
```

Verified dart-sass behavior: `@use "...css" as <ns>` **inlines** the @font-face rules into the compiled CSS (test compiled clean, `@font-face` + woff2 urls present, no leftover `@import`/`@use`). Do NOT use plain `@import "…css"` — dart-sass passes explicit-`.css` `@import` through to the browser **un-inlined**, which would leave a render-blocking `@import` in the final CSS (exactly what PERF-01 forbids). The `as <name>` clause is **mandatory**: a bare `@use "@fontsource/ubuntu/400.css"` fails compilation ("The default namespace \"400\" is not a valid Sass identifier"). Place the three lines at the exact position of today's lines 7-8 — after the existing top `@use` block, before any other rules (valid `@use` placement).

**Versions (discretion resolved):** `@fontsource/ubuntu@5.3.0`, `@fontsource/parisienne@5.3.0` — latest stable both, exact pins, verified on the npm registry 2026-08-20 (no caret, matching the lockstep discipline of 03-CONTEXT D-01).

**Built-output gate (mandatory, PERF-01):** after `gatsby build`, the emitted CSS bundle must contain three `@font-face` blocks (Ubuntu 400, Ubuntu 700, Parisienne 400) whose `url(…woff2)` resolves to real emitted files (webpack emits them as hashed public assets). If the SCSS-`@use` path produces broken `./files/…` urls (css-loader rebase against `src/assets/scss/`), switch to the D-01-sanctioned layout-entry path: add `import "@fontsource/ubuntu/400.css"` (etc.) next to `import "../assets/scss/style.scss"` in `src/components/layout.js:8` — webpack/css-loader resolve node_modules-relative `url()` reliably there. Either path satisfies the contract; the gate is the built CSS. **Test co-change (mandatory):** `phase3-upgrade-matrix.test.js:80-95` ("hoisted the Google Fonts imports…") is **already red in the working tree** (the 5a7d35c `@use` migration moved the font lines off indices 0-1). Rewrite the assertion to: (a) `style.scss` contains zero `@import url(`; (b) `style.scss` contains the three `@use "@fontsource/…` lines; (c) `package.json` pins `@fontsource/ubuntu` + `@fontsource/parisienne`. Same change, suite green again.

### Documented delta (the single intentional 404)

| Element | Today | After | Driver |
|---------|-------|-------|--------|
| `/favicon.ico` (root) | Served from `static/favicon.ico` | **404** — the plugin emits no `.ico`; pages link only `favicon-32x32.png` | D-11 |

This is **accepted and intentional**: legacy browsers that hard-request `/favicon.ico` get a 404, which browsers silently ignore (no user-visible effect; the tab icon comes from the linked PNG). Netlify will log 404s only for direct `/favicon.ico` requests. Do not add a redirect or an `.ico` — that would defeat the payload cleanup. The icon link tags in the head keep the tab icon correct on every modern browser (verification: `grep favicon` on built HTML + browser tab check in the held-out visual pass).
