## Trust Boundaries

| Boundary | Description |
|-----------|-------------|
| formik.js onSubmit → emailjs.sendForm promise → .then/.catch | the success/failure signal crosses here; the old code ignored it (false success) |
| browser → document.location.assign("/thanks") | the redirect crosses here; it must only fire on resolved sends |
| formik.js render → send-error <p role="alert"> | the failure message crosses here; static Italian text, never user input (no XSS) |
| Netlify UI env vars → gatsby build → client bundle | the credentials cross here; frozen at build time (Pitfall 2) |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-12 | Tampering | false-success UX — redirect fires even when the send fails | high | block | Redirect moved inside .then only (D-11); the unskipped regression test asserts assign is NOT called on rejection (D-12) |
| T-04-13 | DoS | double-submit / duplicate emails from a re-enabled button | medium | mitigate | disabled={isSubmitting} guard + Formik awaiting the returned promise (Pitfall 4); EmailJS rate limit 1 req/sec as backstop |
