# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Contract type: PRESERVATION with intentional deltas.** This phase migrates featured images from legacy `gatsby-image` (`Img` + `fluid`) to `gatsby-plugin-image` (`GatsbyImage` + `gatsbyImageData`), swaps `tracedSVG` for BLURRED/DOMINANT_COLOR placeholders, fixes the og:image `[object Object]` bug, and replaces hardcoded English UI/meta copy with real Italian — **no visual redesign** (05-CONTEXT D-04). Every image surface must render **exactly as it does today**: same size, aspect, crop, alt text, and class hooks. The only intentional visual deltas are the placeholder appearance (loading state) and the hero's loading priority; both are locked below. The contract is anchored to the locked decisions D-01…D-19 in 05-CONTEXT.md.

## Image Surface Contract (the core of this phase)

Three surfaces migrate. The query args below are **verified against gatsby-plugin-image 5.16 docs** (05-CONTEXT discretion note resolved):

- `maxWidth`/`maxHeight` are **deprecated** in `gatsbyImageData` → use `width`/`height` (constrained layout).
- `srcSetBreakpoints` is the legacy gatsby-image arg → the resolver arg is **`breakpoints`**.
- `placeholder` is a GraphQL enum: `BLURRED` / `DOMINANT_COLOR` (uppercase, unquoted).
- Default `cropFocus` is `attention` (sharp "attention" strategy) — the legacy fluid pipeline cropped from **center**. To preserve the exact crop, pass `transformOptions: { cropFocus: CENTER, fit: COVER }` on the two surfaces that constrain the box (post-card only — the other two surfaces crop via CSS `object-fit`, not via generation).

| Surface | File (today) | Legacy query | Target `gatsbyImageData` args | Component | Preserved hooks |
|---------|--------------|--------------|------------------------------|------------|-----------------|
| Blog-post featured image | `src/templates/blog-post.js:82` + query:131 | `fluid(quality: 80, srcSetBreakpoints: [350, 700, 1050, 1400])` | `layout: "constrained", quality: 80, breakpoints: [350, 700, 1050, 1400]` | `<GatsbyImage image={getImage(...)} alt={frontmatter.title + " - Featured image"} className="featured-image" objectFit="cover" objectPosition="50% 50%" loading="lazy" />` | `.blog-post .featured-image { min-height: 50vh; border-radius: 12px; margin: 0 auto }` (style.scss:331-335) |
| Index hero | `src/templates/index-page.js:60` + query:20 | `fluid(quality: 80, srcSetBreakpoints: [960, 1440])` | `layout: "constrained", quality: 80, breakpoints: [960, 1440], placeholder: DOMINANT_COLOR` | `<GatsbyImage image={getImage(...)} alt={frontmatter.title + " - Featured image"} className="featured-image" loading="eager" />` | `.home-banner .featured-image { border-radius: 12px }` (style.scss:208-210); wrapper block inside the grid column |
| Post card (blog-list + blog-list-home) | `post-card.js:9` + query (blog-list:27, blog-list-home:46) | `fluid(maxWidth: 540, maxHeight: 360, quality: 80)` | `layout: "constrained", width: 540, height: 360, quality: 80, transformOptions: { fit: COVER, cropFocus: CENTER }` | `<GatsbyImage image={getImage(...)} alt={title + " - Featured image"} className="featured-image" objectFit="cover" objectPosition="50% 50%" />` | `.post-card .featured-image { border-radius: 12px } .post-card .featured-image img { display: block; margin: 0 }` (style.scss:232-237); mobile `min-height: 300px` + radius `12px 12px 0 0` (style.scss:266-268, 292-294) |

### Parity rules (all three surfaces — verify each one)

1. **Aspect/size**: card images box at 540×360 (the legacy maxWidth/maxHeight container) — `width: 540, height: 360` + `fit: COVER, cropFocus: CENTER` reproduces the old center-crop. Blog-post hero and index hero keep **natural aspect** (constrained, no forced dims) — the `min-height: 50vh` / grid column handle layout as today.
2. **objectFit / objectPosition**: `cover` / `50% 50%` — carried over verbatim on post + card (today's explicit props; default `cover` is fine on the hero, which has no explicit prop today — `objectPosition` defaults to `50% 50%`).
3. **Alt text**: `<title> - Featured image` on all three surfaces — **unchanged** (D-04). (Note: English "Featured image" is locked as-is; changing it is NOT in this phase's scope.)
4. **Class hooks**: `className="featured-image"` lands on the GatsbyImage **wrapper** (same element role as legacy `Img`'s wrapper) — all existing SCSS selectors (`.featured-image`, `.featured-image img`, `.post-card .featured-image`) keep matching. If a selector breaks on the `img` element (e.g. `.post-card .featured-image img`), use `imgClassName` to restore it — do NOT rewrite SCSS.
5. **Conditional render**: the `Image ? <GatsbyImage…> : ""` guard pattern is preserved (posts/pages without `featuredImage` render no image — same as today). `getImage()` returns `null` for missing data; the guard stays.
6. **LimitPresentationSize fragment**: drop `...GatsbyImageSharpFluidLimitPresentationSize` — its behavior (no upscale beyond source) is inherent to `constrained` layout; no visual delta.
7. **No gatsby-image imports** remain in `src/` after migration; `gatsby-image` removed from package.json (D-05); `gatsby-plugin-image@5.16.0` added to package.json **and** to the `plugins` array in `gatsby-config.js` (required for SSR).
8. **hero loading**: `loading="eager"` on the index hero only (above-the-fold LCP; GatsbyImage defaults to `lazy` — the contract overrides for the hero). All other surfaces stay `lazy`.

### Seo hardening (D-09, D-11)

- The `image` prop contract is: **string-only**. In `seo.js`, `seo.image` must be the interpolation `${siteUrl}${image || defaultImage}` where `image` is a **URL string** — never a processed-image object (fixes `[object Object]`, IMAG-03).
- Belt-and-suspenders: if a non-string `image` arrives, ignore it and fall back to `defaultImage` (`/assets/heart.png` from `site.json`).
- `blog-post.js:72` resolves the og:image with `getSrc()` from `gatsby-plugin-image` and passes **only the string** into `<Seo image={…}>` (D-10).
- `twitter:image`, `og:image`, and `meta name="image"` all consume the same `seo.image` string — one fix, three outputs.

### Privacy page target (D-19)

Rebuild `src/content/pages/privacy.md` lines ~34-137 to clean markdown:

- **Frontmatter title**: `title: Privacy Policy` → `title: Privacy e Cookie` (the page's visible H1 is already "# Privacy, Cookie e GDPR"; an English `title` leaks "Privacy Policy" into the `<title>`, h1, and meta description — the phase's own "no English in rendered meta" criterion (SEOS-02) requires the Italian title).
- Keep the existing H1/H2 intro prose (lines 7-25) untouched.
- Convert the raw-HTML `<a>`/`<p>` block (lines 34-82) to clean markdown paragraphs or a bulleted list; **preserve every link and its current link text** (Firefox, Chrome, Internet Explorer, Safari, Opera, Google, cookiechoices, Garante).
- Fix ` #### Attiva l'opzione Do Not Track` (line 83) → `#### Attiva l'opzione Do Not Track` (valid H4).
- Convert the trailing raw `<a>` blocks (lines 110-135) to markdown links.
- Deobfuscate the email on line 137: `s.foschi [chiocciola] protonmail.com` → `s.foschi@protonmail.com`.
- Render outcome: valid HTML — no stray `</p>`, no orphan `<a>`, no `####`-as-text.
